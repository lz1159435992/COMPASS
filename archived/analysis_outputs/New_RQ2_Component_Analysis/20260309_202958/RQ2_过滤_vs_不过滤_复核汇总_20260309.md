## 3. 复核口径与“平均时间”定义（关键）

`eval.tex` 中 RQ2 的 `Avg. Time (s)` 明显采用的是：

- **Avg time on solved-only subset**（只在 solved 的实例上取平均）

证据：

- `Table \ref{tab:RQ3-ablation}` 中 `LLM` 的 `Avg. Time = 4.1s`。这不可能是“对所有实例（含 timeout=1200）做 cap 平均”，只能是“只统计 solved 的少数实例平均”。

因此在复算输出中我同时给出两种平均时间：

- `AvgT_all_cap(+tool)s`：对全体实例，timeout 用 cap(1200) 计入平均（用于反映整体成本）
- `AvgT_solved_only(+tool)s`：仅对 solved 的实例求平均（与论文表格口径一致）

### 3.1 1200s 附近边界值处理（关键细节）

本次复算中，判断某个时间 `t` 是否“在 cap=1200 内”，不是直接比较 `t <= 1200`，而是采用：

- 先对 `t` 做 **round-half-up 四舍五入到整数秒**（例如 1200.4 → 1200；1200.5 → 1201）
- 再判断 `round(t) <= 1200`

因此：

- `t <= 1200.4` 会被视为 **未超时（在 cap 内）**
- `t >= 1200.5` 会被视为 **超时（不在 cap 内）**

该规则会影响两处统计：

- **Solved 判定**：需要同时满足 `tool_flag` 为 succeed/success 且 `t` 在 cap 内；即使 flag 为 succeed，但若 `t >= 1200.5` 也会被当作未 solved。
- **AvgT_all_cap(+tool)s**：对未 solved/超时实例，会将时间按 cap=1200 计入全体平均；而 **AvgT_solved_only(+tool)s** 只在 solved 子集上取平均，因此不会纳入这些边界超时的实例。

但由于各方法对应的 info_dict 覆盖范围不同，本次脚本对 LLM/RL variants 的实际可统计条目数为 449（与 SMTimer Z3 info_dict 的 kept=449 一致）。

## 5. 对“RQ2 当前数据是否添加 VAR 过滤”的最终判断

- **是**。`eval.tex` 的 RQ2 ablation 表明确写 Total=337，且 `time_dict_*_106.txt` 的 n=337 与 solved=72/94/... 完全对齐。
- 该 337 的构造过程在旧分析脚本中明确包含 `len(var_count[k]) > 5`。
